# Deploy the API (free tier)

The website is static on Cloudflare Pages. The API (FastAPI) runs on **Render**, with
Postgres on **Neon** and Redis on **Upstash**. All three have free plans that need no credit
card (checked Nov 2026; plans change, so re-check if a sign-up asks for one).

```
browser ── chandrashekhar.pages.dev (Cloudflare Pages, static)
   │  POST /api/v1/contact (later: /api/v1/chat)
   ▼
chandrashekhar-api.onrender.com (Render, Docker: apps/api/Dockerfile)
   ├── Neon Postgres   content tables, contact messages (later: embeddings)
   └── Upstash Redis   rate limit + response cache
```

**Free-plan trade-off:** Render sleeps after ~15 minutes without traffic, so the first request
takes 30–60 s. That's why the site keeps its content bundled (`PUBLIC_CONTENT_SOURCE` empty);
only the contact form waits for the API, and it shows "Sending…" while it does.

## 1. Postgres on Neon (~3 min)

1. Sign up at neon.tech → **Create project**: name `portfolio`, Postgres 17,
   region **AWS Asia Pacific (Singapore)**.
2. Dashboard → **Connect** → turn **Connection pooling OFF** (the API keeps its own pool;
   the pooled URL breaks asyncpg's prepared statements) → copy the connection string.
   It looks like `postgresql://neondb_owner:…@ep-….ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`.
   Paste it as is: the API converts it for asyncpg (`core/config.py → asyncpg_url`).

## 2. Redis on Upstash (~2 min)

1. Sign up at upstash.com → **Create database**: name `portfolio`, region **ap-southeast-1
   (Singapore)**, TLS on.
2. Copy the **Redis URL** that starts with `rediss://default:…@….upstash.io:6379`
   (two "s": TLS).

## 3. API on Render (~5 min + first build)

1. Sign up at render.com with GitHub → **New → Blueprint** → pick
   `chandrashekhar-portfolio`. Render reads [`render.yaml`](../render.yaml).
2. It asks for `DATABASE_URL` (step 1) and `REDIS_URL` (step 2). Paste them → **Apply**.
3. The first build takes a few minutes. On start the container runs `alembic upgrade head`,
   seeds from `content/` (`SEED_ON_START=true`) and serves on Render's port.
4. Check: open `https://<service>.onrender.com/health/ready` →
   `{"status":"ok","checks":{"database":"ok","redis":"ok"}}`. The service name in
   `render.yaml` is `chandrashekhar-api`; if that subdomain is taken, Render adds a suffix,
   so copy the real URL from the dashboard.

`IP_HASH_SALT` is generated by Render. `CORS_ORIGINS` already allows
`https://chandrashekhar.pages.dev`; add your own domain there later.

## 4. Point the website at the API (~2 min)

Cloudflare → Workers & Pages → **chandrashekhar** → Settings → Variables and Secrets →
add `PUBLIC_API_URL` = your Render URL (no trailing slash) → Deployments → **Retry deployment**.

The form then posts to the API. Messages are stored in Neon; read them in Neon's
**SQL Editor**:

```sql
select created_at, name, email, reason, body from contact_message order by created_at desc;
```

## 5. Bot protection: Cloudflare Turnstile (recommended before sharing widely, ~3 min)

Cloudflare → **Turnstile** → Add widget: hostnames `chandrashekhar.pages.dev` and
`localhost`, mode **Managed**.
- **Site key** (public) → Pages variable `TURNSTILE_SITE_KEY`, then redeploy Pages.
- **Secret key** → Render → Environment → `TURNSTILE_SECRET_KEY`.

Set both, or neither: with only the secret, every message is rejected (the API fails closed).

## 6. Email notifications: Resend (optional, ~3 min)

Without it, messages are only stored ("log only" mode). With it, each message is also emailed
to you.

1. Sign up at resend.com with the inbox that should receive messages → API Keys → create one.
2. Render → Environment: `RESEND_API_KEY`, `CONTACT_TO_EMAIL` = that same inbox,
   `CONTACT_FROM_EMAIL` = `Portfolio <onboarding@resend.dev>`. Without your own verified domain,
   Resend only delivers to the account's own address, which is all a contact form needs.

## Later

- **Content edits** go through `content/` + a push (Render redeploys and re-seeds). Once the
  admin panel (Phase 3) edits the database, set `SEED_ON_START=false`.
- **Content from the API** (`PUBLIC_CONTENT_SOURCE=api` on Pages) makes sense once the API
  doesn't sleep (paid plan), or once content is edited in /admin.
- **Keep it awake**: a free uptime pinger (every 10 min on `/health/live`) avoids cold starts.
  It also uses up more of Render's free monthly hours.
